# 代面 Agents as an Interview 完整产品知识库描述

## 一、文档用途

本文档用于完整描述 `Agents as an Interview` 产品，适合作为后续 Agent 撰写产品介绍、项目报告、技术亮点说明、商业计划书、演示稿和答辩材料时的知识库基础。

后续 Agent 使用本文档时，应遵守以下口径：

-   本产品是面向求职训练的 AI Agent SaaS，不是招聘方筛选系统，也不是 ATS 简历管理系统。
-   产品核心不是“AI 随机问问题”，而是“面试前设计、面试中追问、面试后报告、长期咨询记忆”的闭环。
-   涉及技术描述时，应突出产品化价值，避免把文档写成底层代码说明。
-   涉及 MBTI 时，只能表述为“基于本场行为面试证据的表达倾向观察”，不能表述为人格诊断或心理测评结论。
-   涉及长期记忆时，应强调“结构化记忆和 compact profile”，不能理解为无限保存所有聊天并直接塞入模型上下文。
-   涉及 AI 智囊团时，应明确它主要发生在面试开始前，用于生成面试计划，不是每一轮问题都启动多 Agent。

## 二、产品一句话定位

`Agents as an Interview` 是一款面向校招、实习、转岗和早期职场求职者的 AI 求职训练产品。它通过 AI 智囊团、自适应面试官、结构化报告、战略咨询 Agent 和长期记忆，帮助用户完成从“练一场面试”到“持续提升求职能力”的闭环训练。

更简洁的对外表达可以是：

> 代面是一个长期陪伴式 AI 面试训练系统，能根据用户的简历和 JD 设计面试，像真实面试官一样追问，并在面试后给出可复盘、可执行、可持续积累的求职建议。

## 三、产品背景与用户痛点

### 1. 行业与用户背景

校招、实习和早期职场求职中，用户通常需要同时解决岗位理解、简历表达、面试表现和求职策略四类问题。传统准备方式包括刷题、看经验帖、背模板、找朋友模拟、参加线下辅导等，但这些方式存在明显断点：练习不够真实、反馈不够具体、长期记录难沉淀、策略判断缺少依据。

AI 能降低训练成本，但如果只是让大模型生成几个问题，产品价值会停留在浅层问答。`Agents as an Interview` 的目标是把 AI 能力组织成一个完整的训练系统，让用户在每一场面试中获得真实练习，在每一份报告中获得证据反馈，在每一次咨询中形成阶段性行动计划。

### 2. 核心痛点

| 痛点 | 用户表现 | 产品回应 |
|----|----|----|
| 面试练习不真实 | 用户背过题，但面对追问时容易卡住 | 模拟模式、语音朗读、自动录音、倒计时、自适应追问 |
| 反馈过于笼统 | 用户只知道“答得不好”，不知道哪段话有问题 | 结构化评分、逐轮点评、智能批注、推荐回答 |
| 面试题不够个性化 | 通用题库无法结合用户简历和目标岗位 | 基于 JD、简历和目标岗位生成面试计划 |
| 复盘不能持续 | 多场面试之间没有沉淀，问题反复出现 | 历史记录、咨询历史、长期记忆和 compact profile |
| 求职策略不清楚 | 不知道投什么方向、练什么能力、下一步怎么做 | 战略咨询 Agent 结合历史证据给出阶段性建议 |

## 四、目标用户与使用场景

### 1. 核心用户

核心用户是正在准备校招、实习、转岗和早期职业发展的学生与职场新人。他们通常具备一定经历和项目，但缺少面试表达训练，也缺少系统性复盘方法。

### 2. 次级用户

次级用户包括希望展示 AI 产品能力的产品经理、AI 应用开发者和全栈工程师。对这类用户来说，本产品可以展示一个 AI Agent 应用如何从单点 Demo 演进到具备用户系统、语音、报告、历史、记忆和部署能力的完整产品。

### 3. 典型使用场景

| 场景 | 用户目标 | 推荐产品路径 |
|----|----|----|
| 投递前准备 | 理解 JD，确认自己会被问什么 | 创建面试，上传简历和 JD，查看 AI 智囊团生成的主题 |
| 面试前冲刺 | 模拟真实压力，训练临场表达 | 使用模拟模式，开启语音朗读和自动录音 |
| 日常练习 | 逐题优化项目叙事和表达结构 | 使用练习模式，反复回答并查看报告反馈 |
| 行为面准备 | 检查 STAR 表达、冲突处理和个人风格 | 选择行为面，查看行为面和 MBTI 倾向报告 |
| 面试后复盘 | 判断问题出在哪里，准备下一轮 | 查看结构化报告，并从历史面试发起战略咨询 |
| 阶段性规划 | 判断主攻方向和训练重点 | 进入战略咨询，结合多场历史记录和长期记忆讨论 |

## 五、产品闭环

产品闭环可以拆成五个阶段：

``` text
面试前：用户提交公司、岗位、JD、简历和配置
  -> AI 智囊团生成面试计划、主题优先级和开场问题
面试中：AI 面试官根据计划提问，用户语音或文本作答
  -> 系统根据回答质量动态追问、切换主题或结束
面试后：系统生成结构化报告
  -> 输出评分、逐轮点评、智能批注、推荐回答和行为倾向
复盘中：用户查看历史记录并发起战略咨询
  -> 咨询 Agent 结合历史报告和当前问题给出建议
长期中：系统沉淀记忆条目和 compact profile
  -> 下一次咨询更个性化，下一轮训练更有针对性
```

这个闭环是产品的核心差异化。任何对外介绍都应围绕“训练、复盘、咨询、记忆”的连续关系展开，而不应只介绍某一个单点能力。

## 六、核心术语表

| 术语 | 准确定义 | 容易误解的点 |
|----|----|----|
| AI 智囊团 | 面试前由多个 AI 角色共同分析 JD 和简历，生成面试主题和计划 | 不是每一轮面试都多 Agent 讨论 |
| Agent Harness | 模型外层的产品化控制机制，负责上下文、阶段、规则、结果校验和兜底 | 不是单独的 UI 功能，而是系统能力描述 |
| 自适应面试官 | 根据用户回答动态决定追问、切题或结束的 AI 面试官 | 不是固定题库顺序播放 |
| 模拟模式 | 强调真实压力的面试模式，适合正式演练 | 不是无限制自由聊天 |
| 练习模式 | 强调可控练习的模式，适合逐题打磨 | 不是低质量模式，而是训练目标不同 |
| 智能批注 | 把报告判断和用户原回答中的证据片段关联起来 | 不是单纯划重点，也不是改写用户原文 |
| 行为面 MBTI 倾向 | 基于本场行为回答证据观察用户表达倾向 | 不是人格诊断、心理测评或绝对标签 |
| 战略咨询 Agent | 基于历史面试、当前问题和长期记忆给出求职策略建议的 Agent | 不是只复述报告 |
| 结构化记忆条目 | 系统从咨询和面试中抽取的短事实，如方向、短板、训练重点 | 不是完整聊天记录 |
| compact profile | 对多场咨询和记忆条目的长期压缩画像 | 不是把全部历史塞进 prompt |
| 记忆简报 | 咨询页右侧展示的长期画像和参考依据摘要 | 不是原始数据库详情页 |

## 七、功能模块详述

### 1. 首页与产品入口

**功能目标：**\
首页负责让用户快速理解产品，并进入两条核心路径：面试训练和战略咨询。

**用户入口：**

-   创建新面试。
-   查看历史面试。
-   发起战略咨询。
-   查看咨询历史。
-   切换中英文界面。
-   登录或查看登录状态。

**系统行为：**

-   根据用户是否展开首页内容，展示主入口卡片。
-   通过语言切换控制 UI 文案。
-   根据登录状态控制后续数据访问。
-   通过面试入口引导用户进入创建流程，通过咨询入口引导用户进入总结或历史选择流程。

**输出结果：**

-   用户进入面试创建页、历史页、战略咨询页或咨询历史页。

**边界说明：**

-   首页不是营销落地页，也不是功能说明书页面。它的主要作用是作为产品工作台入口。
-   首页不直接生成报告或咨询结论，所有 AI 能力发生在具体业务流程中。

### 2. 用户系统与数据隔离

**功能目标：**\
保证每个用户只能访问自己的面试、报告、咨询、记忆和评分数据。

**用户输入：**

-   用户登录信息。
-   用户在产品中的面试、咨询、删除、评分等操作。

**系统行为：**

-   使用 Supabase Auth 识别用户身份。
-   历史面试、咨询记录、长期记忆和体验评分都与用户归属绑定。
-   服务端写入使用安全密钥，前端只暴露必要的 anon key。

**输出结果：**

-   用户看到自己的历史记录和长期记忆。
-   未授权用户不能读取或修改其他用户数据。

**边界说明：**

-   产品不是企业 HR 管理后台，不提供招聘方候选人池管理。
-   用户级隔离是隐私和安全的基础能力，后续所有历史与记忆功能都依赖该能力。

### 3. 面试创建与配置

**功能目标：**\
收集生成面试所需的基础信息，明确本场面试的岗位背景、训练目标和交互方式。

**主要输入：**

-   公司名称：用于确定面试语境和目标公司背景。
-   岗位名称：用于确定能力模型和问题方向。
-   JD：用于抽取岗位要求、业务场景、硬技能和软技能。
-   简历：用于挖掘用户经历、项目亮点、薄弱点和可追问内容。
-   面试类型：例如专业面、行为面、综合面等。
-   面试难度：影响问题深度、追问力度和结束判断。
-   面试模式：模拟模式或练习模式。
-   AI 模型：当前支持 DeepSeek V4 Pro / Flash 等选项。
-   语音配置：包括是否使用语音、音色、自动朗读和自动录音等。

**系统行为：**

-   将用户输入整理成面试上下文。
-   将简历和 JD 作为后续 AI 智囊团、追问 Agent 和报告生成的重要依据。
-   根据面试类型和难度影响问题风格。
-   根据模式选择不同的交互策略。

**输出结果：**

-   创建一场面试会话。
-   进入 AI 智囊团或面试准备流程。

**边界说明：**

-   JD 和简历越完整，面试主题越精准；如果信息缺失，系统仍可生成通用面试，但个性化会降低。
-   面试配置不是最终报告。配置只决定训练目标和面试上下文。

### 4. 简历解析

**功能目标：**\
将用户上传或输入的简历内容转化为可供 AI 分析的文本上下文。

**用户输入：**

-   简历文件或简历文本。

**系统行为：**

-   解析简历文本，提取可用于面试设计和报告分析的经历信息。
-   将简历内容与 JD、岗位和公司信息合并进入面试上下文。

**输出结果：**

-   可被 AI 智囊团和报告系统引用的简历内容。

**边界说明：**

-   简历解析的目标是支持面试训练，不是自动生成完整简历优化稿。
-   如果简历格式复杂或解析失败，用户需要通过文本补充关键信息。

### 5. AI 智囊团

**功能目标：**\
在正式面试开始前，由多个 AI 角色共同审阅 JD 和简历，设计本场面试的考察主题和提问策略。

**触发时机：**

-   用户完成面试创建后，进入正式面试前。

**角色分工：**

| 角色       | 关注点                         | 输出倾向               |
|------------|--------------------------------|------------------------|
| JD 解构官  | 岗位要求、隐性能力、业务场景   | 必须覆盖的岗位考点     |
| 简历深挖官 | 简历亮点、项目细节、经历疑点   | 值得追问的经历和风险   |
| 面试策略官 | 问题顺序、压力递进、节奏安排   | 一场面试的推进路线     |
| 风险质疑官 | 遗漏、泛化、过于友好、不够真实 | 需要补强或尖锐化的问题 |
| 主持人     | 汇总、去重、排序、形成共识     | 最终面试计划           |

**系统行为：**

-   多角色从不同视角分析同一份 JD 和简历。
-   风险质疑官检查计划是否有遗漏或不够真实。
-   主持人整合输出主题优先级、开场问题和风险关注点。
-   前端可视化展示圆桌讨论过程，让用户感知面试不是随机生成。

**输出结果：**

-   面试主题。
-   主题优先级。
-   开场问题。
-   潜在风险关注点。
-   问题设计依据。

**边界说明：**

-   AI 智囊团主要用于面试计划生成，是高价值但相对高成本的环节。
-   正式面试过程中不应默认每轮都启动智囊团，否则会增加延迟和成本。
-   智囊团输出是面试路线，不是最终报告结论；报告结论需要基于用户实际回答生成。

### 6. 模拟模式

**功能目标：**\
模拟真实面试压力，帮助用户检验临场表达和抗压能力。

**用户输入：**

-   用户通过语音或文本回答 AI 面试官的问题。

**系统行为：**

-   自动朗读问题。
-   支持自动录音。
-   使用倒计时和较少提示制造正式感。
-   更强调连续面试体验，减少用户对配置和历史回答的依赖。
-   根据回答质量决定追问、切题或结束。

**输出结果：**

-   一段接近真实面试的问答记录。
-   面试结束后生成结构化报告。

**边界说明：**

-   模拟模式不是考试判分系统，评分用于训练和复盘。
-   模拟模式不固定题数，题数由主题覆盖、回答质量和最大轮次共同决定。

### 7. 练习模式

**功能目标：**\
让用户在低压力环境下逐题打磨表达，适合日常训练和复盘后再练。

**用户输入：**

-   用户手动听题、录音或输入文本回答。

**系统行为：**

-   保留更多用户控制权。
-   用户可以更方便地查看上下文和历史问答。
-   AI 仍然根据回答进行追问和切题，但整体体验更偏训练而非正式模拟。

**输出结果：**

-   可复盘的练习问答记录。
-   面试结束后生成结构化报告。

**边界说明：**

-   练习模式不是弱化版面试，而是服务不同训练目标。
-   如果用户目标是正式面前压力测试，应优先使用模拟模式。

### 8. 自适应面试官与动态追问

**功能目标：**\
让 AI 面试官根据用户回答实时调整问题，而不是按固定题库机械推进。

**判断依据：**

-   当前主题是否覆盖。
-   回答是否有事实、动作、结果和反思。
-   回答是否偏题或过于空泛。
-   是否有必要继续深挖。
-   是否还有更高优先级主题未覆盖。
-   当前难度和最大轮次是否允许继续追问。

**系统可能动作：**

-   继续追问：当回答浅、缺少证据或存在关键疑点时。
-   切换主题：当当前主题已经覆盖，或更高优先级主题尚未覆盖时。
-   结束面试：当主题覆盖较充分、轮次达到上限、回答信号不足或用户表达出结束意图时。

**输出结果：**

-   下一轮问题。
-   追问或切题理由隐含在面试流程中。
-   面试结束信号。

**边界说明：**

-   动态追问不是无限追问，系统需要最大轮次和结束判断。
-   面试官不能离开求职和目标岗位语境展开无关闲聊。
-   追问应围绕当前面试目标，不应为了追问而追问。

### 9. 语音识别 ASR

**功能目标：**\
将用户语音回答转写为文本，作为面试记录和报告生成依据。

**用户输入：**

-   用户录制的音频回答。

**系统行为：**

-   使用豆包 ASR 进行语音转写。
-   转写期间启用提交锁，避免 ASR 尚未完成时保存空回答。
-   如果转写成功，将文本写入回答记录。
-   如果转写失败，提示用户重录或切换文本输入。

**输出结果：**

-   用户回答的文本转写。

**边界说明：**

-   ASR 转写文本是报告分析的重要依据，应尽量避免空回答进入报告。
-   如果用户口音、环境噪音或网络问题影响转写，用户需要手动修正或改用文本。

### 10. 语音合成 TTS

**功能目标：**\
让 AI 面试官以语音方式朗读问题和部分咨询内容，提高真实感和陪伴感。

**用户输入：**

-   用户选择的音色或语音配置。

**系统行为：**

-   使用豆包 TTS 将 AI 问题或回复转为语音。
-   支持自动朗读和手动播放。
-   与面试模式联动，模拟模式更强调自动朗读。

**输出结果：**

-   面试官问题或咨询回复的语音播放。

**边界说明：**

-   TTS 是交互体验增强，不改变报告评分逻辑。
-   TTS 失败时不应阻断文本面试，用户仍可阅读问题并作答。

### 11. AI 面试报告

**功能目标：**\
将面试过程转化为可复盘、可行动的结构化反馈。

**触发时机：**

-   面试结束后。

**输入内容：**

-   用户简历和 JD。
-   面试配置。
-   AI 智囊团生成的面试计划。
-   面试全程问答记录。
-   用户选择的语言和面试类型。

**报告结构：**

-   综合评分。
-   五个核心维度评分。
-   整体点评。
-   逐轮回答分析。
-   亮点总结。
-   核心问题。
-   提升建议。
-   推荐回答。
-   智能批注。
-   行为面相关报告，若本场适用。

**核心评分维度：**

| 维度       | 含义                                       |
|------------|--------------------------------------------|
| 岗位匹配度 | 回答是否体现目标岗位需要的能力、经历和理解 |
| 回答完整度 | 是否交代背景、任务、行动、结果和反思       |
| 逻辑性     | 表达是否有结构，因果是否清晰               |
| 专业度     | 是否体现岗位知识、业务理解和项目深度       |
| 沟通表达   | 是否清楚、简洁、可信、有说服力             |

**输出结果：**

-   用户可以阅读的完整报告。
-   可保存到历史记录的结构化报告数据。

**边界说明：**

-   报告评分用于训练和自我提升，不代表真实企业录用结果。
-   报告应基于本场回答证据，不应凭空扩展用户没有表达过的经历。
-   中文面试应输出中文报告，英文面试应输出英文报告，避免语言混杂。

### 12. 智能批注

**功能目标：**\
让用户看到 AI 反馈对应的是原回答中的哪一段证据，提升报告可信度和可执行性。

**输入内容：**

-   用户每轮回答文本。
-   报告中的优点、问题和建议。

**系统行为：**

-   先将用户长回答切成更稳定的语义片段。
-   再由 AI 判断哪些片段支撑优点或问题。
-   将证据片段与点评关联展示。

**输出结果：**

-   回答原文中的高亮片段。
-   与片段对应的点评说明。

**边界说明：**

-   智能批注应尽量引用用户原文，不应大幅改写后再匹配。
-   批注的目标不是把整段回答全部标满，而是标出最关键证据。

### 13. 推荐回答

**功能目标：**\
给用户提供可参考的优化表达，帮助用户理解同一问题可以如何更结构化地回答。

**输入内容：**

-   原问题。
-   用户原回答。
-   目标岗位和 JD。
-   报告分析出的短板。

**系统行为：**

-   基于用户已有经历重组表达。
-   补充合理的结构和表达方式。
-   尽量避免凭空创造用户没有提供的事实。

**输出结果：**

-   每轮问题或重点问题的参考回答。

**边界说明：**

-   推荐回答不是要求用户逐字背诵。
-   推荐回答应服务于表达结构和内容补强，不应捏造项目经历、数据或成果。

### 14. 行为面报告与 MBTI 倾向

**功能目标：**\
帮助用户理解自己在行为面试中的表达风格、岗位环境适配度和潜在风险。

**适用场景：**

-   行为面试。
-   综合面试中包含较多行为问题的场景。

**输入内容：**

-   行为问题回答。
-   用户讲述的项目、冲突、协作、决策和反思。
-   目标岗位特征。

**系统行为：**

-   基于回答证据判断表达倾向。
-   输出四组 MBTI 倾向条或类似维度解释。
-   分析用户在目标岗位环境中的优势和风险。
-   保留动态追问能力，继续深挖行为经历中的细节。

**输出结果：**

-   MBTI 倾向说明。
-   证据解释。
-   岗位环境匹配分析。
-   面试优势。
-   潜在风险和改进建议。

**边界说明：**

-   MBTI 倾向报告不是人格诊断。
-   结论只能来自本场行为面试证据。
-   不能把用户永久贴标签，应使用“本场表达更倾向于”这类谨慎表述。

### 15. 历史面试

**功能目标：**\
保存用户的面试训练记录，让用户能够查看、筛选、复盘和继续咨询。

**保存内容：**

-   面试基本信息。
-   面试配置。
-   问答记录。
-   面试报告。
-   创建时间和用户归属。

**用户操作：**

-   查看历史面试。
-   搜索和筛选。
-   打开报告详情。
-   删除记录。
-   基于某场历史面试发起战略咨询。

**输出结果：**

-   可回看的面试记录。
-   可作为战略咨询依据的历史报告。

**边界说明：**

-   历史面试是用户个人训练资产，不应被其他用户访问。
-   删除操作以用户界面结果为准，用户点击删除后应从当前界面移除。

### 16. 战略咨询入口

**功能目标：**\
让用户基于一场或多场历史面试，与 AI 咨询师讨论下一步求职策略。

**用户输入：**

-   选择的历史面试记录。
-   用户当前问题或咨询目标。
-   可选模型配置。

**系统行为：**

-   读取所选历史面试报告。
-   读取与用户相关的长期记忆和 compact profile。
-   进入咨询对话。

**输出结果：**

-   新的咨询会话。

**边界说明：**

-   战略咨询不是重新生成面试报告，而是在报告基础上做更高层的方向判断和行动建议。
-   用户可以围绕单场面试咨询，也可以围绕多场历史记录咨询。

### 17. 战略咨询对话

**功能目标：**\
回答用户关于求职方向、面试问题、训练计划和岗位选择的开放式问题。

**咨询主题示例：**

-   我适合投什么岗位？
-   这场面试最大问题是什么？
-   我是不是不适合这个方向？
-   下一周应该怎么练？
-   多场面试里我反复出现的问题是什么？
-   某个报告结论的依据是什么？

**系统行为：**

-   优先回答用户当前问题。
-   结合历史面试证据补充判断。
-   必要时追问一个关键信息，而不是连续盘问。
-   输出可执行建议，例如训练重点、表达框架、投递策略和下一步计划。
-   咨询结束后总结本次咨询结论，并更新长期记忆。

**输出结果：**

-   多轮咨询对话。
-   本次咨询结论。
-   可被后续记忆系统抽取的关键信息。

**边界说明：**

-   咨询 Agent 不应只复述报告，也不应脱离证据做空泛鼓励。
-   咨询应遵循用户问题优先，而不是 AI 主导长篇训话。
-   咨询建议是训练和求职策略建议，不是录用保证。

### 18. 咨询记忆简报

**功能目标：**\
在咨询过程中向用户展示 AI 使用了哪些长期信息，增强透明度和可解释性。

**展示内容：**

-   已选面试。
-   当前咨询状态。
-   长期画像摘要。
-   本次参考重点。
-   已经解决的问题。
-   折叠的依据来源。

**系统行为：**

-   默认收起，不挤压聊天区。
-   用户需要时可展开查看。
-   以摘要方式呈现，不直接堆叠完整历史报告和聊天。

**输出结果：**

-   咨询页右侧信息栏。

**边界说明：**

-   记忆简报不是数据库原始记录展示。
-   记忆简报应帮助用户理解 AI 判断依据，而不是替代咨询回复。

### 19. 咨询历史

**功能目标：**\
保存用户的战略咨询记录，支持后续查看、筛选、删除和记忆管理。

**保存内容：**

-   咨询基本信息。
-   关联的历史面试。
-   多轮咨询消息。
-   本次咨询结论。
-   记忆开关状态。
-   是否完成。

**用户操作：**

-   查看历史咨询。
-   搜索和筛选咨询记录。
-   删除咨询。
-   开启或关闭某次咨询对长期记忆的贡献。
-   查看已完成状态。

**输出结果：**

-   可回看的咨询记录。
-   可作为长期记忆来源的咨询结论。

**边界说明：**

-   已完成咨询不可继续写入新对话，避免旧结论被误改。
-   关闭记忆后，该咨询不应继续作为后续咨询的有效长期上下文。

### 20. 长期记忆系统

**功能目标：**\
让产品能够跨多次面试和咨询理解用户阶段性状态，同时控制上下文长度。

**记忆来源：**

-   历史面试报告。
-   战略咨询结论。
-   用户在咨询中确认或补充的信息。
-   已解决或被否定的旧问题。

**记忆结构：**

| 层级 | 内容 | 作用 |
|----|----|----|
| 结构化记忆条目 | 主攻方向、暂不建议方向、反复问题、训练重点、已问问题、面试证据等短事实 | 精准召回具体事实 |
| compact profile | 稳定优势、长期短板、当前方向、最近变化、已解决问题和依据来源 | 快速提供长期用户画像 |

**系统行为：**

-   从咨询结论和历史证据中抽取短事实。
-   对多场咨询进行压缩，形成长期画像。
-   后续咨询优先读取 compact profile，再补充少量结构化证据。
-   关闭或删除咨询记忆后，尝试基于剩余有效记录重建长期画像。

**输出结果：**

-   更个性化的咨询回复。
-   更少重复建议。
-   更可控的上下文长度。

**边界说明：**

-   长期记忆不是完整聊天堆叠。
-   过期、关闭、删除或已解决的信息不应继续强行影响新咨询。
-   记忆应服务于当前问题，不应让 AI 每次都主动把话题拉回旧问题。

### 21. 用户反馈评分

**功能目标：**\
收集用户对面试和咨询体验的主观评分，帮助后续优化产品。

**用户输入：**

-   面试体验 1 到 5 星评分。
-   咨询体验 1 到 5 星评分。

**系统行为：**

-   将评分与用户、会话类型和具体记录关联保存。
-   可用于后续分析体验质量和功能改进方向。

**输出结果：**

-   体验评分记录。

**边界说明：**

-   用户反馈评分不是面试表现评分。
-   反馈评分用于评价产品体验，不应和 AI 报告分数混淆。

## 八、关键业务流程

### 1. 新建并完成一场面试

``` text
用户进入首页
  -> 点击创建面试
  -> 输入公司、岗位、JD、简历
  -> 选择面试类型、难度、模式、模型和语音配置
  -> AI 智囊团生成面试计划
  -> 用户进入模拟或练习面试
  -> AI 提问，用户语音或文本作答
  -> 系统动态追问、切题或结束
  -> 生成结构化报告
  -> 保存到历史面试
```

### 2. 从报告进入战略咨询

``` text
用户打开历史面试或报告
  -> 点击发起战略咨询
  -> 选择一场或多场面试作为依据
  -> 系统读取报告、咨询历史和长期记忆
  -> 咨询 Agent 回答用户当前问题
  -> 用户多轮追问
  -> 咨询结束后保存结论
  -> 抽取记忆条目并更新 compact profile
```

### 3. 后续咨询使用长期记忆

``` text
用户再次发起咨询
  -> 系统读取 compact profile
  -> 根据当前问题选择相关结构化记忆
  -> 生成短记忆摘要
  -> 咨询 Agent 结合当前问题、历史证据和记忆摘要回复
```

## 九、产品与技术优势

### 1. 不是普通 Chatbot，而是任务型 Agent 产品

普通聊天机器人可以回答问题，但很难稳定完成一场面试训练。`Agents as an Interview` 在模型外层加入上下文管理、阶段控制、主题覆盖、追问策略、报告结构和记忆系统，让 AI 能力围绕具体任务运行。

### 2. 多 Agent 提升面试设计质量

AI 智囊团通过多个角色共同分析 JD 和简历，减少单一模型漏掉关键考点的风险。JD 解构官保证岗位相关性，简历深挖官保证个性化，策略官保证面试节奏，风险质疑官保证问题更真实，主持人负责输出可执行计划。

### 3. 自适应追问模拟真实面试节奏

真实面试不会严格按题库走。产品通过回答质量、主题覆盖和难度上限判断下一步动作，让面试既有计划，又能根据用户表现调整。

### 4. 证据化报告让反馈可执行

报告不只是分数，而是将用户原回答、AI 点评、证据批注和推荐回答连接起来。用户可以知道自己哪段话有效、哪段话有问题，以及下一次如何改。

### 5. 长期记忆让产品具备陪伴性

通过结构化记忆条目和 compact profile，产品能记住用户长期方向、反复短板和已解决问题。后续咨询不需要每次从零开始，也不会因为历史过多导致上下文失控。

### 6. 端到端 SaaS 闭环完整

产品具备登录、创建面试、语音交互、报告生成、历史记录、战略咨询、长期记忆、体验评分和用户级数据隔离能力。它不是单点模型演示，而是围绕真实用户流程构建的完整 AI 应用。

## 十一、后续 Agent 写作时的统一口径

### 1. 可以强调的产品亮点

-   面试前有 AI 智囊团，不是随机出题。
-   面试中有动态追问，不是固定题库。
-   面试后有证据化报告，不是泛泛总结。
-   面试历史可以进入战略咨询，不是一次性练习。
-   长期记忆让多次咨询形成连续画像，不是每次从零开始。
-   语音交互提升真实感，文本输入提供兜底。
-   用户级数据隔离让产品具备 SaaS 基础。

### 2. 不应夸大的点

-   不应说产品能保证拿到 offer。
-   不应说报告等同于真实企业面试官评价。
-   不应说 MBTI 报告是人格诊断。
-   不应说长期记忆保存所有信息并每次完整读取。
-   不应说 AI 智囊团在每一轮面试中都参与决策。
-   不应说产品已经具备企业招聘管理、候选人筛选或 HR 后台功能。

### 3. 推荐表达

可以使用：

> 产品通过多 Agent 面试设计、自适应追问、证据化报告和长期记忆咨询，构建了一个面向求职者的闭环训练系统。

不建议使用：

> 产品只是一个 AI 面试聊天机器人。

可以使用：

> 行为面报告基于用户本场回答证据观察表达倾向。

不建议使用：

> 产品可以准确判断用户人格类型。

可以使用：

> 长期记忆通过结构化条目和 compact profile 控制上下文长度。

不建议使用：

> 系统会把用户所有历史聊天都发给大模型。

## 十三、后续发展方向

### 1. 报告可视化增强

后续可以把 AI 智囊团在面试前预判的主题和风险，与面试中的实际回答进行“预判 vs 命中”对照。用户可以看到哪些考点已经覆盖，哪些只是部分覆盖，哪些完全遗漏。

### 2. 成长看板

基于历史面试和咨询记录，展示用户累计训练次数、得分变化、反复问题、岗位方向变化和训练计划完成情况。

### 3. 咨询方法库增强

围绕岗位方向判断、企业筛选、项目包装、行为面表达、AI 替代风险、城市平台选择等场景，沉淀更多可复用的咨询技能。

### 4. 记忆召回增强

继续优化 memory selector、结构化记忆和轻量 Graph Memory，让长期咨询更个性化，同时避免上下文膨胀。

### 5. 多端与供应商扩展

优化移动端体验，支持更多登录方式、更多语音供应商和更多模型选择。

## 十四、总结

`Agents as an Interview` 的核心价值，是把 AI 从“能聊天”推进到“能完成求职训练任务”。它围绕真实求职准备流程，将面试设计、面试执行、报告复盘、战略咨询和长期记忆连接起来。

对用户来说，它提供更真实、更具体、更连续的面试训练体验。对产品来说，它形成了多 Agent 面试设计、自适应追问、证据化报告和长期记忆咨询的差异化闭环。对技术展示来说，它体现了 AI Agent 应用从模型调用到 SaaS 产品落地的完整能力。
