# Agents as an Interview · 产品技术特色

## 一句话定位

`Agents as an Interview` 不是一个简单的 AI 问答工具，而是一个面向求职训练的 Agent SaaS 产品。它把短期的真实模拟面试、面试后的 AI 报告复盘，以及长期的战略咨询对话串成一个闭环，帮助用户从“练一场面试”逐步走向“持续提升求职能力”。

## 核心技术特色

### 1. Agent Harness：让 AI 面试官可控、可追踪、可复盘

产品的核心不是直接把用户回答交给模型，而是在模型外层设计了一套 **Agent Harness**。这套 Harness 负责统一编排上下文、面试状态、提问规则、主题覆盖、结果校验和兜底机制。

因此，AI 面试官不是随机追问，而是在每一轮根据用户回答、已覆盖主题、剩余轮次和面试类型，判断下一步应该继续追问、切换主题，还是结束面试。这样既保留了 Agent 的灵活性，也避免了偏题、重复提问或无限追问。

### 2. AI 智囊团：先设计面试，再开始提问

在正式面试前，系统会启动 **AI 智囊团**，从多个视角共同审阅用户的简历和 JD：

- JD 解构官关注岗位要求和隐性能力模型。
- 简历深挖官关注候选人经历、亮点和疑点。
- 面试策略官关注问题顺序、压力递进和面试节奏。
- 风险质疑官负责检查遗漏、泛化和不够真实的问题。
- 主持人最终整合成一份可执行的面试计划。

这让产品生成的不是“几道题”，而是一场有主题优先级、有风险预判、有验证路径的面试。

### 3. 自适应提问链路：模拟真实面试节奏

真实面试不会机械地按题库走。当前产品中的面试 Agent 会持续评估：

- 用户回答是否充分；
- 当前主题是否已经覆盖；
- 是否需要补一个关键追问；
- 是否应该切到更高优先级主题；
- 是否已经达到合理轮次或应该结束。

这条自适应链路让面试更接近真实场景：回答浅时会被追问，回答偏题时会被拉回，关键主题没覆盖时会主动切换，低信号或无效回答过多时会结束面试。

### 4. 报告闭环：从“预判”到“验证”

AI 报告不只给一个分数，而是把面试过程转化成可复盘的证据。报告会围绕岗位匹配、回答完整度、逻辑性、专业度和沟通表达进行评分，并结合逐轮回答生成点评、批注和推荐回答。

更重要的是，报告会回收 AI 智囊团在面试前设定的主题，形成：

```text
面试前预判 -> 面试中验证 -> 面试后复盘 -> 战略咨询继续跟进
```

这让产品从一次性练习工具，升级为可持续优化的求职训练系统。

### 5. 战略咨询 Agent：从短期面试走向长期成长

面试结束后，用户可以基于历史面试记录继续和战略咨询 Agent 对话。咨询 Agent 不只是复述报告，而是结合历史记录、当前问题和长期记忆，帮助用户判断方向、识别反复问题、制定下一步训练计划。

产品中设计了结构化记忆和 compact 长期画像：系统不会把所有历史聊天和报告都塞给模型，而是把关键结论压缩成短事实和长期画像。这样既能保持个性化，又能减少上下文膨胀，让咨询更像一个了解用户长期状态的求职教练。

### 6. SaaS 化产品闭环

产品已经围绕真实用户使用链路完成了基本闭环：登录、创建面试、语音或文本作答、生成报告、保存历史、发起战略咨询、长期记忆、体验评分和用户级数据隔离。

从产品思路上，它不是单点 AI 功能，而是：

```text
模拟面试体验
  -> 结构化报告反馈
  -> 历史记录沉淀
  -> 战略咨询对话
  -> 长期用户画像
  -> 下一轮更有针对性的训练
```

## 对外介绍话术

我把这个产品定位为一个面向求职训练的 Agent SaaS。它的核心不是简单调用大模型生成问题，而是用 **Agent Harness** 把模型约束成一个可控的 AI 面试官：系统会管理上下文、面试阶段、主题覆盖、追问策略和结果校验，让面试既有真实感，也有稳定性。

在面试开始前，AI 智囊团会综合简历、JD、技术要求和潜在风险，先设计本场面试应该验证什么；面试过程中，面试官 Agent 会根据用户回答自适应追问或切换主题；面试结束后，报告会把原本预判的主题和实际回答表现对应起来，给出可执行反馈。长期来看，战略咨询 Agent 会结合多场历史面试和长期记忆，持续帮助用户判断方向和改进训练策略。

这个产品的技术特色可以概括为：**Agent Harness 控制面试过程，AI 智囊团提升面试设计质量，自适应提问模拟真实面试节奏，结构化报告完成复盘，长期记忆支撑持续成长。**
